## 1. 未解決の指摘2点

**① 信号ありでも残る無断横断1件 → 原因が分かりました（仕様どおりの動作）**
- 信号あり（普通）の1ループで記録すると、無断横断は1件で、交差点から約7.9マス離れた場所を歩いていた人でした。
- 迂回距離は約14マス（往復で 2×(7.9−1)）で、横断歩道を使う条件（迂回6マス以内）を超えるため、無断で渡ります。「遠い人は使わない」という、企画書どおりの動作です。
- 対応: 修正せず、仕様どおりと報告します。ステージ1では、信号の位置で変わる要素として残します。

**② 速度設定がループ間でリセットされる → コードを読む限り、再現できていません**
- 速度は `speed_index` だけで決まり、ボタンを押したときにしか変わりません。ループの切り替え（`reset_loop`）では触っていません。
- 考えられるのは、低フレームのとき、1フレームで進められるステップの上限（8）に当たって、実質の速さが落ちる場合です。ただし、これは「リセット」ではありません。
- 再現した状況（どの画面で、何を押して、いつ戻ったか）を教えてください。ステージ1は24時間の1回で終わるので、ループ自体がなくなります。再発したら、原因を特定します。

## 2. 作業計画（実装順）

動くものを、3回に分けて公開します（公開は、そのつど動作を確認してから）。

**第1回: 遊べる土台（地図・自転車・24時間・失敗する難しさ）**
1. 「資金」→「開発ポイント」に表記を統一。開始100（`tuning.gd`）
2. **A. 街を小さく、密に**: 交差点の間隔を16→**12マス**（中心線が x=±6, z=±6）に詰める。建物は小さく、初期カメラを近づける。※下の質問1
3. **自転車**を追加: 通勤者・買い物客の一部が自転車で移動する。優先度は 歩行者＞自転車＞車両（低優先側が必ず止まって譲る）。車線は車と共有し、速度は歩行者と車の中間（初期値 2.2マス/秒）。自転車専用レーンは作らない
4. **B. 24時間の4つの山**: 朝（学校前）、昼（買い物）、夕（帰宅）、夜（通過交通）で、問題の質が変わるように予定表と通過交通を作り直す
5. **C. 失敗する難しさ**: 「何もしないと不満度が100になり、2時間続いて失敗」「山ごとに判断し直すとクリア」になるよう調整。調整のために、台本どおりに動く「疑似プレイヤー」をテストに用意する

**第2回: 開発ポイントの経済（バブル・誘導員）**
6. **誘導員**: 費用50。朝と下校の各1時間半だけ稼働（機能は信号と同じ）。配置変更は不可、取り壊しのみ（50%返還）。**D. 迷う選択肢にする**: 最初に誘導員を置くか、貯めて信号を増やすか
7. **不満バブル**: 待たされている人の頭上に出現。タップで +5。寿命は実時間4〜6秒（速度に連動しない。時間停止中は凍結）。同時表示は最大4個。出現率の自己調整（出た総数で下がり、停滞すると上がる）。同じ人にはクールダウン
8. バブルの演出と**音**: 膨らんで破裂、破片、「+5」がカウンターへ飛ぶ。短時間の連鎖で音程が上がる。音は、スクリプトで作る小さな波形ファイル（数十KB）で用意する

**第3回: 結果まで一続き（予報・結果・ダイジェスト）**
9. **予報画面**（時刻・場所・理由のリスト。項目を選ぶと地図の該当場所が光る）→ 事前配置 → 進行
10. **結果画面**: ★評価（簡易）、**事後診断**（「信号が児童◯人の横断を安全にした」等、人数で）、**ダイジェスト再生**（ヒヤリの瞬間のハイライトを含む）、リトライ。失敗画面は「何時に・どこで上限に達したか」
11. 計測の記録と報告レポート。確認用の切り替えボタン（24時間／朝ピーク、晴れ／雨）は、通常画面から外して `?debug=1` のときだけ出す

## 4. 不明点（質問）

回答がなくても、括弧内の案で進めます。

1. **交差点の間隔は12マスでよいですか。**「11マス前後」ですが、道路の中心線を格子に合わせるため、左右対称に作れる12（中心線 ±6）にします。11にすると、地図が左右非対称になります（案: 12）。
2. **自転車は、車と車線を共有する簡易な扱いでよいですか。** 自転車専用レーンは「作らないもの」なので、自転車は車と同じ車線を、遅い車のように走ります。車は自転車の後ろで詰まります（案: 共有）。
3. **誘導員の「夕」は下校時間帯でよいですか。** 仕様書は「夕方＝下校時間帯」ですが、夕方の通勤ラッシュ（17〜19時）とは別の時間です。通勤の帰り道には効きません（案: 仕様どおり 15:00〜16:30）。
4. **1日は6:00から翌6:00までとしてよいですか。** 朝の山から始めて、夜の山で終わる形です（案: 6:00開始）。
5. **確認用ボタン**（24時間／朝ピーク、晴れ／雨）は、通常画面から外してよいですか（案: `?debug=1` のときだけ表示）。
6. **速度リセットの再現手順**を教えてください（上記②）。
