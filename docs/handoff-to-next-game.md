# 引き継ぎメモ — 交通整理パズル（本リポジトリ）から次のゲームへ

方針転換により、次のゲームは内容がまったく別になる。本リポジトリは前作の記録として残し、次は新しいリポジトリ・新しいセッションで始める。

## 1. 前作の到達点
- Godot 4.7.2（GDScript／Compatibility／Web シングルスレッド）で、信号と誘導員を置いて街の不満度を下げるゲームのステージ1（4交差点・24時間）まで作った。
- 最終コミット: 8c4ce7e（ブランチ `claude/confident-hopper-q0twii`）。公開版は GitHub Pages。
- スマホ実機（iPhone, Safari）で FPS 60、シム 0.7〜1.7 ms を確認（車・歩行者 計約 120〜140）。操作性は「良い感じ」との評価。
- 仕様の詳細は `docs/stage1-report.md`、`docs/roadmap.md`。

## 2. 方針を変えた理由
- 「混んだら信号を置く」の反応の繰り返しで、先を読んで選ぶ要素がなく、パズルとして面白くならなかった。
- バブル（収入）は動く対象にくっついて押しにくく、色も薄くて見逃された。
- 置いた効果がシミュレーションのぶれで分かりにくく、自分の一手のせいだと感じにくかった。

## 3. 次のゲームに持っていけるもの
- ビルドと公開（そのまま流用可）
  - `tools/setup_godot.sh`: Godot と Web テンプレートの導入（冪等・SHA512 検証）
  - `tools/build_web.sh`: Web 書き出しとサイズ表示
  - `.github/workflows/pages.yml`: push で Pages に公開。Settings → Pages → Source を「GitHub Actions」にする必要あり。ブランチ名は新しいものに直す
  - `game/export_presets.cfg`: Web 書き出し設定（シングルスレッド、COOP/COEP 不要）
- 日本語 UI フォント: `tools/make_font.sh`（Web ではシステムフォントが使えないため、文言を変えたら再実行）
- 効果音の生成: `tools/make_sounds.py`、`game/scripts/core/sfx.gd`（消音切り替えも）
- 横画面・タッチ前提の UI（`emulate_touch_from_mouse`、大きめのボタン）の作り方: `game/scripts/ui/hud.gd`
- ブラウザ確認: `build/web` を `python3 -m http.server` で配信し、Playwright（Chromium, `--use-angle=swiftshader`）で開く。ヘッドレスの FPS はスマホの FPS ではない

## 4. 新しいゲームで避けたいこと
- 数値の調整から先に始めない。まず「何を選ぶ遊びか」「一手の結果が分かるか」を、できるだけ小さく作って触って確かめる。
- シミュレーション（ぶれのある挙動）を土台にすると、検証と調整に時間が吸われる。結果が決まっている固定問題のほうが、パズルとして評価しやすい。
- 動くものをタップさせる操作は、スマホでは押しにくい。
- 実機の FPS は、公開版を開いた左上の表示をユーザーに読んでもらう。
- 仕様の食い違いや、仕様にない追加（前作では不満の倍率など）は、勝手に決めず報告する。

## 5. 新しいセッションの始め方
1. 新しいリポジトリを作る（このセッションは `haruman9898/pazzle` にしか書けない）。
2. Muse の新しい企画書・仕様書を `docs/spec/` に置く。
3. `CLAUDE.md` を新しいゲーム用に書き直す（本リポジトリの `CLAUDE.md` は交通整理専用）。
4. 上の「持っていけるもの」をコピーして、空のプロジェクトで Web 書き出しと公開が通ることを最初に確認する。
