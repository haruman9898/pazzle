# 仕様書 v0.1 — 交通整理系パズルゲーム（仮題）

作成: 2026-11-24 / 状態: v0.1。企画書 v1.0（仮完成）の決定事項を実装仕様に落としたもの。
根拠資料: `traffic-control-企画書-v1.0.md`、`claude-code-context-traffic-game.md`、各草案ファイル
分担: 企画・仕様・レビュー = Muse、実装 = Claude Code
数値に「初期値」とあるものは試作で調整する前提。「TBD」は未決定事項で、勝手に確定させないこと。

## 1. 技術前提

- エンジン: Godot 4.3以降、言語: GDScript
- 配信先: Web（シングルスレッド版書き出し、COOP/COEPヘッダー不要）
- 画面: 横画面、タッチ操作前提（マウスでも操作可能にしておく）
- ロジックとモデルの分離: 交通ロジック（グリッド、経路、不満度）はモデル（見た目）に依存しない。モデルは footprint（占有マス）・高さ区分・ピボット（設置基準点）の規約に従い、後から差し替え可能にする
- 容量: 音声・画像の容量を常に意識する。初回読み込み容量の上限数値は TBD（試作の実測後に設定）
- 性能計測: 試作段階からスマホブラウザでのFPSを計測できる状態にする

## 2. 画面と状態遷移

### 2.1 画面状態
1. **予報画面**: ステージ開始前。「時刻・場所・理由」のリスト。項目選択でマップ上の該当場所がハイライトされる
2. **事前配置**: 時間は動かない。インフラ級も設置できる
3. **進行中**: 24時間が流れる。通常表示は上部バー＋右下の3本線ボタンのみ
4. **設置モード**: 時間停止。右下ボタン→画面が左にズレ右に設置パネル（Coffee Inc方式）→手段選択→パネルが閉じ全画面で配置→確定／キャンセル
5. **設備ポップアップ**: 既存設備タップで表示。時間停止
6. **結果画面**: ★評価、ダイジェスト再生、リトライ／次へ

### 2.2 上部バー（進行中・常時表示）
- 時計（ゲーム内時刻）、不満度ゲージ、残り資金、速度切替ボタン（早い／普通／遅い、右上）
- 時計に紐づく追加表示は入れない（決定済み）

### 2.3 カメラ
- アイソメトリック視点。**回転は360度自由回転**（90度スナップはしない・決定 2026-11-24）。ズームも可能
- 操作の割り当て（決定 2026-11-24）: 回転 = 1本指で長押ししてからドラッグ／ズーム = 2本指（ピンチ）／マップ移動 = 1本指ドラッグ
- 定位置（標準の向き）に戻るボタンを用意する。自由回転で向きを見失った時のため
- 道路を隠す建物は自動で半透明化する。任意の角度に対応するため、カメラからの視線で遮蔽を判定する方式とする（フェード対象と閾値は試作で調整）

## 3. 時間仕様

- 1ステージ = ゲーム内24時間。通常速度で実時間 約5分
- 速度: 早い＝約2.5分、普通＝約5分、遅い＝約10分（初期値。倍率はTBD）
- 時間が止まる場面: 設置モード、設備ポップアップ、事前配置、予報画面
- 敗北条件: 不満度が上限（100）のままゲーム内2時間継続したら失敗。猶予はゲーム内時間で計測するため、時間停止中は進まない

## 4. マップ仕様

- グリッドベース。道路・歩道・建物・交差点をマスで管理する
- ステージ1: 交差点4つ程度。住宅エリア、オフィス1棟、小学校1校、商店1〜2軒。駅は置かない
- 街の外との出入口: マップ端の道路・歩道。通過トリップと街外ODが使う
- 24時間の光: 朝＝柔らかい光、昼＝明るい、夕＝オレンジ、夜＝街灯と窓明かり。時刻に連動して照明が遷移する（試作期から実装）

## 5. トリップとエージェント仕様

### 5.1 トリップ
- 属性: 出発地、目的地、目的、移動手段、出発時刻、希望到着時刻
- 建物ごとに発生・受入プロファイル（時間帯別）を持ち、プロファイルが片道トリップを発生させる。同一エージェントの往復管理はしない
- 通過トリップ: 車両・人・自転車すべてに一定割合で発生。入口→出口はランダムな組み合わせ
- ステージ1の住民: 通勤者、児童、買い物客。乗り物は車と自転車

### 5.2 移動手段とモーダルシフト
- 手段はトリップ生成時に距離と種類で決まる
- バス・電車の導入後、その路線沿いのODを持つ車トリップの一部が公共交通に切り替わる（モーダルシフト）。切替率は路線とODの近さで決める（率は試作で調整）

### 5.3 挙動ルール
- 歩行者: 最短経路。横断は自分の進路上が基本。信号のある横断歩道までの迂回がパラメータ距離以内なら横断歩道を使う
- 車両: 最短時間経路。信号があれば従う
- 自転車: 車と歩行者の中間。自転車レーンがあれば使う
- **事故の絶対禁止**: 接触は仕様上発生しない。優先度は歩行者＞自転車＞車両。低優先側が必ず停止して譲る
- ヒヤリ（急ブレーキ）は発生してよい。回数を数え、不満と安全性評価に使う

## 6. 設備仕様

| 手段 | 区分 | 費用 | 効果 | 副作用・制約 |
|---|---|---|---|---|
| 信号機 | 設備級 | 100 | 設置地点で車両・歩行者が信号に従う。横断がその地点の横断歩道に集約される（詳細は6.1） | 間隔設定を誤ると車列が伸びる。設置し過ぎると車の停止時間が増える |
| 交通誘導員 | 設備級 | 50 | 信号の無い場所で信号機と同じ整理誘導 | 稼働は朝と夕方の各1時間30分のみ。配置変更不可 |
| 自転車専用レーン | 設備級 | 150 | 区間の分離（ヒヤリ消滅・速度低下なし）、自転車の高速化、接続時のモーダルシフト（詳細は6.1） | 車線が減り車の流れが悪化 |
| 歩道橋 | 設備級 | 250 | 横断による車の停止が消える | 遠回りを嫌う人は使わない |
| バス交通システム | 設備級 | 600 | モーダルシフトで車総数が減る。バス停は候補から選択（詳細は6.1） | 停留所周辺に歩行者が集中 |
| トンネル | インフラ級 | 1,500 | 山を貫通し、迂回をなくして所要時間を短縮する（詳細は6.1） | 開始前のみ設置可。山のあるマップ専用 |
| 電車 | インフラ級 | 3,000 | 大量の人を車から移せる | 開始前のみ設置可。駅周辺に人が集中 |

### 6.1 設置ルール（決定 2026-11-24）
- **信号機**: 交差点単位ではない。**道路のどこにでも設置可能**（交差点でも、普通の道路の途中でもよい。例: 学校の近くの道路上に置くと通学がしやすくなる）。横断歩道は信号とセットでその地点に生まれる。設置し過ぎると車両の停止時間が増え、不満増加につながる（過剰設置がそのまま副作用になる）
- **交通誘導員**: 道路のどこにでも設置可能
- **歩道橋**: どこにでも設置可能（道路を横切る地点）
- **バス**: 設置するとバス交通システムが自動で成立し、定期的にバスが来て人々を輸送する。路線はプレイヤーが設計しない。ただし**バス停は候補地点から選ぶ（採用 2026-11-24）**: 導入時に建物近くの候補地点が表示され、上限数までタップで選べる。選択中のバス停には利用圏の円と「乗り換わりそうな人数」の見込みを表示する
- **電車**: 大規模マップで活躍する手段。マップの端（上下左右／上下／左右の組み合わせ）に駅が出現し、駅同士を繋ぐ線路が自動で引かれる。一定間隔で電車が来て人々を輸送する
- **トンネル**: マップ上に山が存在するステージで活用する。山で迂回を強いられている交通に対し、山の部分にトンネルを設置すると迂回なしで短時間に目的地へ着ける
- **自転車専用レーン（採用 2026-11-24）**: 道路の区間に設置する。効果は3点: ①その区間では自転車と車が分離され、ヒヤリが消え、互いの速度低下もなくなる ②自転車の移動が速くなる ③レーンが住宅と学校・オフィスなどを途切れずに繋ぐと、その経路の短距離トリップ（徒歩と車の一部）が自転車に乗り換わる（モーダルシフト）。バラバラのレーンでは③は起きず弱い。副作用: 車線が減り車の流れが悪化する。児童は徒歩のまま（自転車への乗り換わり対象は通勤者・買い物客など）

- 信号の間隔: 「短い／普通／長い」の3段階プリセット。秒数の初期値は試作で設定（TBD）。設置時に選び、後から変更可
- 誘導員の稼働時間: 朝＝登校時間帯の1時間30分、夕＝下校時間帯の1時間30分。具体的な時刻は学校プロファイルに連動（初期値 TBD）
- 取り壊し: 即時可能。費用の50%が返金される
- 資金: ステージごとに固定。残資金は次ステージに持ち越さない（評価にのみ反映）
- 段階アンロック: ステージ進行で手段が解放される。ステージ1は信号機と誘導員のみ

## 7. 不満度仕様

- 各エージェントが個人不満（0〜100）を持つ。加算要因: 遅延（実所要時間 vs 期待所要時間）、待ち時間、ヒヤリ
- 街全体のゲージは、街にいる全員の個人不満から算出する（算出方式の詳細は試作で確定。平均ベースを想定）
- 不満の伝染: 近くで待つ人の不満が少しずつ周囲に広がる
- 減衰: 目的地に到着した人の不満はゲージから抜ける。時間経過でも緩やかに下がる
- 調整目標（ステージ1）: 対策なしで朝ピーク時に上限近く／適切な信号1基で60前後／信号＋誘導員で40以下／昼は20以下に減衰
- 表示: 進行中はゲージ＋小さなアイコン程度。理由の詳細は時間停止中のみ表示

## 8. 交通予報の生成

- 建物プロファイル × 時間帯から「何時に・どこが・なぜ混むか」を生成し、ステージ開始前に提示する
- 予報は無料・基本形のみ（詳細版の課金は不採用・決定済み）
- **予報と実際の一致（決定 2026-11-24）**: 建物から発生するトリップは予報どおりに確定させる（予報はプレイヤーとの約束。ブレさせない）。ランダム性は通過交通の量だけに小さく入れ、勝敗を左右しない範囲に留める

## 8.5 音（決定 2026-11-24）

- 優先度: 最初はゲームシステムの確立と操作感の確認が最優先。**音は最低限**にし、クオリティ向上は後回し
- 最低限の内訳: 設置音、取り壊し音、クリア／失敗のジングル、ヒヤリ時の短いブレーキ音、BGMは雰囲気のループ1本。ミュート切り替えあり
- 後でクオリティを上げる段階では、音・BGM・サウンドを生成できる人気のAIやリポジトリの利用を検討する（ユーザーの意向）

## 8.6 画面構成とセーブ（決定 2026-11-24）

- 画面の流れ: タイトル → ステージ選択 → 予報 → プレイ → 結果
- セーブ: ブラウザ内保存（ステージ解放、★記録、設定）。外部アカウントは作らない。ブラウザのデータを消すと消える点は現段階では許容

## 8.7 チュートリアル（決定 2026-11-24）

- 説明画面は作らず、ステージ1の設計自体で教える（1つの仕組みずつ、安全な場面で体験させる）
- 最初の予報は1件だけ。最初に使える手段は信号から始め、学校前に置く場面で「置いたら歩行者の動きが変わる」を見せる
- 操作（回転・ズーム・移動）だけは短い図解を初回のみ表示する

## 8.8 失敗時の流れ（決定 2026-11-24・暫定）

- 失敗画面では「何時に・どこで不満が上限に達したか」の要約を出す
- リトライは同じステージ・同じ資金ですぐ再開でき、ペナルティなし
- 暫定方針: 実際にプレイした後に確認し、適宜修正する

## 9. 評価仕様

- クリア: 24時間を終えること
- ★評価の材料: 残資金、最大不満度、ヒヤリ件数、歩行者の安全・満足（独立軸）
- ★のしきい値は TBD（試作後に設定）

## 10. ダイジェスト再生

- クリア後に24時間をタイムラプス再生する
- 実装方針: 再生に必要な記録（時刻ごとのエージェント位置・主要イベント）をステージ進行中に残す方式を想定。詳細は試作後に詰める
- 宣伝動画としての書き出しは保留（作らない。今は対象外）

## 11. 開発順序（ハイブリッド方式・決定済み）

1. **トラック1（遊び）グレーボックス**: 1交差点＋車＋信号＋歩行者の無断横断＋不満度の簡易カウンタ。判定基準は「信号を置いたら歩行者が横断歩道に寄る」瞬間が面白いか
2. **トラック2（見た目）品質目標サンプル**: 同じ1交差点をジオラマ品質で作り、制作時間・FPS・容量を実測する
3. **合流判断**: 両結果を見て、ローポリ（照明は最終仕様）でステージ1本制作へ
