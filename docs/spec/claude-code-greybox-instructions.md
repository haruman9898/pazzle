# Claude Code 指示書 — トラック1 グレーボックス最小試作

作成: 2026-11-24 / 状態: 渡し準備済み
根拠: `spec-v0.1.md`、`traffic-control-企画書-v1.0.md`、`claude-code-context-traffic-game.md`
目的: 「置いたら街が変わる」面白さを、見た目にお金をかける前に判定する

## この試作で答えたい問い

**信号機を置いたら、歩行者が横断歩道に寄るようになり、街の動きが目に見えて変わるか？**

この問いへの答えが「はい」なら本制作へ進む。「いいえ」ならルール側を直す。見た目はこの試作の評価対象ではない。

## 技術前提

- Godot 4.3以降、GDScript、Web書き出し（シングルスレッド版）
- 横画面・タッチ操作（マウスでも可）
- ロジックとモデルを分離すること。見た目はすべて箱と色（グレーボックス）でよい
- 試作時点で、最終モデルと同じ footprint（占有マス）・高さ区分・ピボットで作ること。ここがズレると差し替えが作り直しになる

## 作るもの（スコープ）

### マップ
- 1交差点のみ。十字路＋歩道＋横断歩道の位置だけを置く
- 建物は置かない。代わりに交差点の四隅を「発生・吸収エリア」として扱う（住宅・学校・オフィスの代わり）

### エージェント
- 車両: 対向車線を走り、交差点で直進・右左折する
- 歩行者: 歩道を歩き、道路を渡る。渡る場所は自分の進路上が基本（＝無断横断する）
- 自転車: 含めない（グレーボックスの範囲外。ステージ1本制作で追加する）
- 通過トリップ: 含めない。発生は交差点の四隅のエリアからとする

### トリップ生成
- 時間帯プロファイルが片道トリップを発生させる方式（同一エージェントの往復管理はしない）
- 朝のピークを再現する簡易プロファイルでよい。例: 開始から一定時間、歩行者と車両の発生量が多い
- 24時間フルではなく、朝ピーク相当の短いループ（例: ゲーム内2〜3時間分）で試せればよい。時間の長さは試作で調整してよい

### 信号機（唯一の設置可能手段）
- 費用100、資金300。グレーボックスでは資金の表示と消費だけあればよい
- 設置フロー: 右下の3本線ボタン → 時間停止 → パネルから信号機を選択 → パネルが閉じて全画面マップで配置 → 仮配置 → 確定／キャンセル
- 間隔プリセット: 短い／普通／長い の3段階。秒数の初期値は試作で決めて報告すること（TBD）
- 信号がある交差点では車両と歩行者が信号に従う。信号が無い状態では歩行者は車を止めて渡り、車両は譲り合わず渋滞する

### 歩行者の横断ルール
- 信号のある横断歩道までの迂回がパラメータ距離以内なら横断歩道を使う
- パラメータは調整可能にし、初期値と「信号が効き始める距離感」を報告すること

### 事故の絶対禁止（仕様上の絶対条件）
- 接触事故は発生させないこと。優先度は歩行者＞自転車＞車両。低優先側が必ず停止して譲る
- ヒヤリ（急ブレーキ）は発生してよい。回数を数えて表示すること

### 不満度（簡易カウンタでよい）
- 個人不満（0〜100）を各エージェントが持つ。加算要因は遅延・待ち時間・ヒヤリ
- 街全体のゲージは現在いる全員の平均ベースで算出（詳細は試作で確定）
- ゲージとヒヤリ件数を画面に表示すること。目標値の目安:
  - 信号なしで朝ピーク時に上限近くまで上がる
  - 信号を適切に置くと60前後に収まる

### 時間とUI（最小限）
- 上部バー: 時計、不満度ゲージ、残り資金、速度切替（早い／普通／遅い）
- 時間停止: 設置メニューを開いている間は時間が止まる
- カメラ: アイソメトリック視点、360度自由回転、ズーム、定位置に戻るボタン。操作の割り当ては仕様書どおり（回転 = 1本指長押し→ドラッグ／ズーム = 2本指／マップ移動 = 1本指ドラッグ）。道路を隠す建物はないためフェードは不要
- 信号の設置場所について: 本仕様では信号は道路のどこにでも置けるが、この試作では交差点への設置で検証すればよい（路上設置のケースはステージ1本制作で検証する）
- 24時間の光の変化はグレーボックスでは不要

## 作らないもの

- ジオラマ品質のモデル・テクスチャ・ライティング演出（トラック2の範囲）
- 信号機以外の手段（誘導員、歩道橋、自転車レーン、バス、トンネル、電車）
- 自転車、通過トリップ、駅、建物の時間帯特性のフル実装
- 交通予報画面、★評価、ダイジェスト再生、クリア／失敗画面（失敗条件のカウントだけは内部で持つ）
- 容量上限の最適化（計測と報告だけでよい）

## 受け入れ基準（この試作の合格ライン）

1. 信号なしの状態で、歩行者が車を止めて渡り、渋滞と不満度の上昇が目に見える
2. 信号を置くと、歩行者が横断歩道に寄る動きが目に見える
3. 信号を置くと不満度ゲージが下がり、置かないと上がる、という因果がプレイヤーに伝わる
4. ヒヤリ件数が数えられ、信号の有無で変化する
5. Web書き出しでスマホブラウザで動作し、FPSとファイルサイズを報告できる

## 報告してほしいこと

- 信号プリセット（短い／普通／長い）の秒数の初期値と、その決め方
- 歩行者が横断歩道を使う迂回距離パラメータの初期値
- 不満度ゲージの算出方式として採用した具体的な式
- スマホブラウザでのFPSと、Web書き出しのファイルサイズ
- 遊んでみて「面白さの芯が成立しているか」の所感と、改善が必要なルールがあればその指摘
- 試作中に決めた数値は、すべてこのファイルの「初期値」として分かる形で残すこと
