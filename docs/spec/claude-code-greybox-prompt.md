あなたはゲーム開発の実装担当です。企画・仕様は企画側（ユーザーとMuse）で決定済みで、あなたはその実装に集中してください。

## 渡すファイルと読む順番

1. `claude-code-greybox-instructions.md` — 今回の作業指示書。作るもの・作らないもの・受け入れ基準・報告事項が書いてあります。最優先で従ってください
2. `traffic-control-企画書-v1.0.md` — 企画書。ゲームの狙いと、なぜこの設計になったかの経緯が書いてあります。判断に迷った時の背景として読んでください
3. `claude-code-context-traffic-game.md` — プロジェクト全体の決定事項、作らないもの（不採用）、保留、未決定の一覧です
4. `spec-v0.1.md` — 仕様の正本です。指示書と食い違う場合は指示書を優先し、食い違いを報告してください

## 今回の作業

トラック1「グレーボックス最小試作」を実装してください。目的は、見た目にお金をかける前に「信号機を置いたら、歩行者が横断歩道に寄るようになり、街の動きが目に見えて変わるか」という面白さの芯を判定することです。見た目は箱と色で十分です。

## 守ってほしいこと

- 技術前提: Godot 4.3以降、GDScript、Web書き出し（シングルスレッド版）、横画面・タッチ操作
- ロジックとモデルは分離し、試作時点から最終モデルと同じ footprint・高さ区分・ピボットで作ってください
- 仕様書の「TBD」「未決定」の項目は、勝手に確定させないでください。試作に必要な初期値は置いて構いませんが、その場合は「試作で置いた初期値」として報告に明記してください
- 「作らないもの」「不採用」の項目は実装しないでください
- 仕様に曖昧な点や矛盾があれば、勝手に解釈を固定せず、作業を止めずに進められる範囲で進め、報告の中で質問として挙げてください

## 成果物

1. Webで動作するグレーボックス試作（スマホブラウザで開いて遊べる形）
2. 報告レポート（Markdown）: 指示書の「報告してほしいこと」の全項目を含めてください
   - 信号プリセットの秒数の初期値と決め方
   - 歩行者が横断歩道を使う迂回距離パラメータの初期値

   - スマホブラウザでのFPSとWeb書き出しのファイルサイズ
   - 受け入れ基準1〜5への自己チェック結果
   - 遊んでみた所感（面白さの芯が成立しているか）と、ルール側の改善提案があればその内容
   - 仕様への質問・矛盾の指摘があればその一覧
