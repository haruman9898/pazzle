# Claude Code 受け渡し用コンテキスト — 交通整理系パズルゲーム

最終更新: 2026-11-24
このファイルは企画側（ユーザー＋Muse）で決定した事項を、実装担当のClaude Codeへ渡すための記録です。随時更新されます。
未決定の項目は未決定と明記します。「作らないもの」「保留」を実装に含めないでください。

## プロジェクト概要

- ジャンル: ステージ制トラフィックコントロール・パズル
- コンセプト: 「無秩序に秩序を作る」。併存軸: 「眺めていても楽しいプレイ画面」
- 分担: 企画・仕様・レビュー = Muse、実装 = Claude Code

## 決定事項

### ゲームルール
- 舞台は街（建物、道路、歩道、車両、バイク、通行人、自転車）。ステージ開始時は交通の仕組みが何も無い
- 住民・車両は目的地到達を最優先に自己中心的に動く（通行人は車を止めて横断、車両はルール無視の右左折など）。結果として渋滞・混乱が起き、不満度が上がる
- プレイヤーはステージごとの固定資金で交通整理の手段を設置し、不満度を抑えて24時間（ゲーム内）を終えればクリア
- フロー: 交通予報を見る → 事前配置 → 24時間の進行 → 介入（任意・何度でも）→ 判定
- 交通予報: 開始前に「何時に・どこが・なぜ混むか」を提示する（建物の時間帯特性から生成）。無料・基本形のみ
- 介入: 設備設置メニューを開いている間は時間がストップする。その間も新規設置・調整・取り壊しが可能
- 24時間の波: 朝夕の通勤ラッシュ、登下校時は子供の通行量が増加、夜は交通量減（夜固有の問題は検討中）
- 建物の時間帯特性: ステージが進むと建物が追加される（病院、大型商業施設、テーマパーク、学校など）
  - 大型商業施設: 土日は昼前後がピーク（入退場で混雑）
  - テーマパーク: 朝の開園前が最も混雑
  - 学校: 登下校時に子供が増加
  - 病院: 詳細は今後詰める
- 手段の区分:
  - 設備級（進行中も即時設置可、取り壊しも即時）: 信号機（青／赤の切り替え間隔はプレイヤーが設定）、歩道橋、自転車専用レーン、交通誘導員、バス交通システム
  - インフラ級（ステージ開始前のみ設置可）: トンネル、電車
  - すべての手段に副作用を持たせ、万能手は作らない（副作用の具体例は企画書参照）
- 不満度: 全体1本のゲージ。理由は見える化するが表示は控えめに（進行中は小さなアイコン程度、詳細は時間停止中の介入画面で表示）
- 不満の伝染: 採用。渋滞に巻き込まれた人の不満が近くの人にも少しずつ広がる
- 敗北条件: 不満度が上限のままゲーム内2時間続いたら失敗（即失敗ではない）。全ステージ共通で固定
- ステージ時間: 通常速度で24時間＝約5分。画面右上に速度切替ボタン（早い／普通／遅い）。早い＝約2.5分、遅い＝約10分は候補値
- 評価: クリア時に★評価（草案）。「歩行者の安全・満足」を車の流れとは独立した評価軸として入れる（採用）
- 対策の段階アンロック: 採用。ステージ進行で新しい手段が解放される
- クリア後の1日ダイジェスト再生: 採用。24時間をタイムラプスで振り返る

### 画面・アート
- 視点: アイソメトリック＋**360度自由回転**（90度スナップはしない・決定）。定位置に戻るボタンあり。道路を隠す建物は自動フェード（半透明化）し、任意角度に対応するためカメラ視線で遮蔽判定する
- 画面: 横画面、タッチ操作、スマホブラウザ対応
- アート段階方針: 最初はローポリで試作を固め、その後ジオラマ風にリアリティを追求する
  - ロジックとモデルを分離し、モデルは差し替え可能にする
  - 試作時点で最終モデルと同じ占有マス（footprint）・高さ区分・設置基準点（ピボット）で作る
  - 照明・影・建物自動フェードは試作期から実装する
  - 性能予算（スマホブラウザでのFPS、Web容量）を試作期から計測する
- 24時間で街の光が変わる: 朝は柔らかい光、昼は明るく、夕方はオレンジ、夜は街灯と窓明かり

### 技術
- エンジン: Godot 4.3以降、言語: GDScript
- 最初の配信先: Web。シングルスレッド版書き出しが標準のため、ホスティングにCOOP/COEPヘッダーは不要。C#のWeb書き出しは4.xでは不安定なため使わない
- ファイルサイズ: 音声・画像の容量を仕様段階から意識する（上限数値は未決定）
- GSAP／three.jsはGodot内では使わない（演出はGodot標準のTween）。Impeccable／HallmarkはGodot UI向けではない。FFmpeg／OpenScreenは将来の宣伝動画用

### 開発の進め方（ハイブリッド方式）
- トラック1（遊び）: グレーボックス最小試作。構成は「1交差点＋車＋信号＋歩行者の無断横断＋不満度の簡易カウンタ」。判定基準は「信号を置いたら歩行者が横断歩道に寄る」瞬間が面白いか
- トラック2（見た目）: 並行して同じ1交差点をジオラマ品質で作る品質目標サンプル。制作時間・FPS・容量を実測する
- 合流判断後に、ローポリ（照明は最終仕様）でステージ1を本制作する

### 目的地システム（2026-11-24 決定）
- 街の動きは「トリップ（出発地→目的地、目的、移動手段、出発時刻、希望到着時刻）」の集まりとして扱う。建物がトリップを発生・受入し、建物の時間帯特性＝発生・受入プロファイル
- トリップは時間帯プロファイルが発生させる片道トリップとする（同一エージェントの往復管理はしない）
- 住民の種類は順次増やす。ステージ1は通勤者・児童・買い物客の3種＋車でプレイ感を確かめる
- モーダルシフト: バス・電車を導入すると路線沿いの車トリップの一部が公共交通に切り替わり、車の総数が減る
- 歩行者が信号を使う条件はパラメータ方式: 横断歩道までの迂回が一定距離以内なら使う
- 通過トリップ: 車両・人・自転車すべてに、街を通過するだけのトリップを一定数入れる。入口→出口の組み合わせはランダム（右→上、左→下など。単純な右→左だけにしない）
- **事故は絶対に発生させない**: 人・自転車・車両の接触事故は仕様上起こらない。優先度は歩行者＞自転車＞車両とし、低優先側が必ず止まって譲る。接触はしないが、急ブレーキ・ヒヤリの回数は数えて安全性の評価に使う（採用）
- 不満の発生: 遅延（実所要時間が期待所要時間を大きく超える）、待ち時間、ヒヤリ。詳細は `destination-system-draft-v0.1.md`

### 設置ルール（2026-11-24 決定）
- 信号機: 交差点単位ではなく、道路のどこにでも設置可能（交差点でも路途中でも可。学校近くの路上に置けば通学がしやすくなる）。横断歩道は信号とセットで生まれる。設置し過ぎると車の停止時間が増えて不満が上がる
- 誘導員・歩道橋: 道路のどこにでも設置可能
- バス: 設置すると自動でシステム成立し定期運行で人を運ぶ。路線は設計しないが、バス停は候補地点から上限数までタップで選ぶ（利用圏の円と乗り換わり見込み人数を表示）
- 電車: 大規模マップ用。マップ端に駅が出現し、線路が自動で繋がり、一定間隔で運行する
- トンネル: 山のあるマップで、山の部分に設置して迂回をなくす手段
- 自転車専用レーン: 道路の区間に設置。効果は「区間の分離（ヒヤリ消滅・速度低下なし）」「自転車の高速化」「住宅と目的地を途切れず繋ぐと短距離トリップが自転車に乗り換わるモーダルシフト」。バラバラだと弱い。副作用は車線減少による車の流れ悪化。児童は徒歩のまま
- カメラ操作: 回転 = 1本指長押し→ドラッグ／ズーム = 2本指／マップ移動 = 1本指ドラッグ

### その他の仕様（2026-11-24 決定）
- 音: 最低限で開始（設置音、ジングル、ブレーキ音、BGMループ1本、ミュートあり）。クオリティ向上は後回しで、その際は音・BGM生成の人気AIやリポジトリの利用を検討する
- 画面構成: タイトル → ステージ選択 → 予報 → プレイ → 結果。セーブはブラウザ内保存のみ（解放・★・設定）
- チュートリアル: 説明画面なし。ステージ1の設計で教える（予報は最初1件、手段は信号から）。操作の図解だけ初回表示
- 失敗時: 「何時に・どこで上限に達したか」の要約を表示し、同条件で即リトライ可・ペナルティなし（暫定。プレイ後に見直す）
- 予報の正確さ: 建物発のトリップは予報どおり確定。ランダム性は通過交通の量のみで、勝敗を左右しない

### 操作・UI（2026-11-24 決定）
- 設置メニューはCoffee Inc方式: 右下の3本線ボタンをタップするとプレイ画面が左にズレ、右側に設置パネルがスライドインする。常時表示のバー／パネルでプレイ画面を狭くしない。参考画像 `samples/ui-reference-coffeeinc-menu.jpg`
- パネルで手段を選んだらパネルは閉じ、配置は全画面マップで行う。一連の設置操作が終わるまで時間は止まったまま
- 設置は仮配置→確認ボタンで確定する（タップ即設置はしない）
- 信号の間隔プリセットは設置時に選び、後から設備をタップして変更もできる
- 予報画面は「時刻・場所・理由」のリスト形式で、項目を選ぶとマップ上の該当場所が光る
- 詳細は `ui-draft-v0.1.md`

### 数値（2026-11-24 決定・初期値、試作で調整）
- 費用はポイント制。信号機1基 = 100が基準。誘導員50、自転車専用レーン150、歩道橋250、バス600、トンネル1,500、電車3,000
- ステージ1の資金は300
- 取り壊し: 費用の50%が返金される
- 誘導員: ステージ単位の雇用。配置変更は不可で、取り壊し（消去）のみ可。役割は信号の無い場所での整理誘導で、機能は信号機と同じ。ただし稼働は朝と夕方の各1時間30分のみ（具体的な時刻は仕様で登下校時間に合わせて設定）。存在目的は子供の登下校の安全
- 残した資金: 次ステージに持ち越し不可。クリア評価（★）にのみ反映する
- 信号の切り替え間隔: 「短い／普通／長い」の3段階プリセットで設定。連続調整（スライダー）はしない
- 不満度の調整目標（ステージ1）: 対策なしだと朝のピークで上限近く、適切な信号1基で60前後、信号＋誘導員で40以下、昼は自然に20以下へ減衰。詳細は `numbers-draft-v0.1.md`

### ステージ1の構成（2026-11-24 決定）
- 位置づけ: 実質的なチュートリアル。「予報を読む → 信号を置く → 街が変わる」を体験させる
- マップ: 交差点4つ程度の小さなグリッド。住宅エリア、オフィス1棟、小学校1校、商店1〜2軒。駅は置かない（後のステージで登場）
- 住民: 通勤者、児童、買い物客 ＋ 車両 ＋ 自転車（自転車はステージ1から入れる）
- 1日の波: 朝は学校前で児童の横断と通勤の車がぶつかるのが主問題。昼は買い物で穏やか。夕は朝の逆向き。夜は通過交通中心
- 使える手段: 信号機と交通誘導員のみ。資金は信号2〜3基＋誘導員1〜2人が置ける程度（全交差点には置けない）
- 詳細は `stage1-draft-v0.1.md`
