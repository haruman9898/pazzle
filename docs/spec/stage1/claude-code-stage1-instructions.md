# Claude Code 指示書 — ステージ1試作（開発ポイント＋不満バブル込み）

作成: 2026-11-25 / 状態: 渡し準備中
根拠: `spec-v0.1.md`（13節の追加決定を含む）、`claude-code-context-traffic-game.md`、`bubble-system-proposal-v0.1.md`、`stage1-draft-v0.1.md`
目的: 新しい経済（開発ポイント＋不満バブル）で、ステージ1が「5分間、判断し続けられる遊び」になるかを判定する

## この試作で答えたい問い

**開始所持わずか（信号1基分）から始めて、バブルを弾いて貯め、途中で追加開発する循環は面白いか？「やることがない時間」は減るか？**

グレーボックスで確認済みの芯（信号で街が変わる）は前提としてよい。今回は経済とステージ1の広さで遊びが成立するかを見る。

## 前提として引き継ぐもの（グレーボックス＋その後の修正・採用分）

- 信号の設置フロー、時間停止、間隔プリセット、確定後の自動再開、拡大済みUI
- 採用済みの追加要素のうち実装済み／実装中のもの（色の波、不満の内訳表示、熱マップ、事後診断、仕草、光と音の変化、ダイジェスト等）は、この試作でも維持する
- 未解決の指摘2点（速度設定がループでリセットされる件、信号ありでも残る無断横断1件の発生条件）も、この試作の中で解消または原因報告をする

## 作るもの（スコープ）

### ステージ1の構成（決定済み）
- マップ: 交差点4つ程度の小さなグリッド。住宅エリア、オフィス1棟、小学校1校、商店1〜2軒。駅なし
- 住民: 通勤者、児童、買い物客 ＋ 車両 ＋ 自転車（ステージ1から）
- 1日の波: 朝=学校前で児童の横断×通勤の車（主問題）、昼=買い物で穏やか、夕=朝の逆向き、夜=通過交通中心
- 使える手段: 信号機と交通誘導員のみ
- 24時間フル（通常速度で約5分）。予報画面 → 事前配置 → 進行（介入可）→ クリア／失敗 → 簡易★評価まで一通り通す

### 開発ポイント経済（2026-11-25決定）
- 通貨は「開発ポイント」に統一。「資金」の表記は使わない
- 開始所持: **100**（信号機1基分）。事前配置では信号1基か誘導員2人までの範囲しか置けない
- 費用: 信号機100、誘導員50。取り壊しは50%返還
- 残ポイントは次ステージに持ち越さない

### 不満バブル（2026-11-25決定。詳細は `bubble-system-proposal-v0.1.md`）
- 止まっている／待たされている人の頭上に出現。タップで弾くと開発ポイント+5（初期値、調整可）
- 寿命は実時間4〜6秒、速度設定に連動させない。時間停止中は凍結する
- 同時表示は最大3〜5個。出現率は「出現総数で少し下がり、停滞すると少し上がる」自己調整を入れる
- 破裂の演出と音を作り込む（膨らんで破裂、破片、「+5」がカウンターへ飛ぶ、短時間の連鎖で音程が上がる）
- 1人からの連続出現にはクールダウンを入れる

## 追加要件（2026-11-25採用。Claude Code提案A〜D）

以下4点は、Claude Codeの提案をユーザーが採用したもの。この試作の要件として実装する。

- **A. 街を小さく、密に**: 交差点の間隔を16マス→**11マス前後**に詰める。建物は小さめにし、最初のカメラは街に近づける。同じ人数でも混雑がはっきり見える密度にする（「置いた効果が見える」芯を取り戻すため）
- **B. 24時間の山を全部使う**: 朝（学校前）→昼（買い物）→夕（通勤の帰り）→夜（通過交通）の4つの山で、それぞれ問題の質が変わるようにする。時間帯ごとに対策を見直す必要が出ることが狙い（単調さの解消）
- **C. 緊張感と結果**: 難易度は「放っておくと失敗する」水準に調整する（不満度が上限に達し、2時間継続で失敗する条件が実際に迫ること）。クリア／失敗の結果画面は、★評価・事後診断・ダイジェストまで一続きにつなぐ
- **D. 誘導員を迷う選択肢にする**: 誘導員は仕様どおり（朝夕各1時間30分のみ稼働、機能は信号と同じ、配置変更不可）。開発ポイント経済での迷い方は「最初に誘導員を置くか、バブルで貯めて信号を増やすか」という順番の判断として設計する（旧・資金300前提の配分の迷いではない）

## 作らないもの
- 信号・誘導員以外の手段（歩道橋、自転車レーン、バス、トンネル、電車）
- 駅、山、病院などの追加建物
- インフラ級の扱い（開始所持との両立）は未決定のため触らない
- 改善案A〜E（fun-fix-proposal-v0.1）は採用判断がまだのため実装しない。ただし計測（下記）だけは入れる

## 受け入れ基準
1. 開始所持100で事前配置ができ、朝のピーク中にバブル収入で2基目の信号（または誘導員追加）に手が届く
2. バブルが「詰まっている場所」の目印として読める（ランダム出現に見えない）
3. バブルを弾く行為が気持ちいい（音・破裂・数字の飛び方）。主観でよいので所感を報告する
4. 渋滞を放置して稼ぐ動きが最適になっていない（放置すると不満度で負けに近づく）
5. 24時間を通して「何もしない時間」がグレーボックスより減っている
6. 何も対策をしないと実際に失敗する（敗北条件が机上のものではない）。逆に、山ごとに判断し直せばクリアできる

## 報告してほしいこと
- バブルの出現数／弾いた数／取り逃した数（1プレイ分）。収入の時間推移（何時頃に2基目が買えたか）
- 意思決定の回数（設置・間隔変更・取り壊しなど、プレイヤーが判断した回数）
- 信号プリセットの秒数、不満度の計算式、ファイル容量（前回未提出分の回収）
- 速度リセットと無断横断1件についての解消状況または原因
- 経済バランスの所感（開始100、バブル+5が妥当か。信号2基目が遠すぎ／近すぎないか）
