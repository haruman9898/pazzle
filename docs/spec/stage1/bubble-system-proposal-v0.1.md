# 不満バブル・システム提案 v0.1（2026-11-25 採用決定）

発案: ユーザー（2026-11-25）。Plague Inc.（伝染病株式会社）のバブルを調査し、本作向けに設計した叩き台。
決定（2026-11-25）: バブル採用。あわせて通貨は「開発ポイント」に統一し、「資金」の概念は廃止。ステージ開始時の所持はわずか（最小単位のみ）で、バブルで貯めて開発していく形に決定した。本文書の「経済への組み込み方」は、この決定（単一通貨・少数スタート）で確定。2層案（案1）は不採用。
位置づけ: 「やることが少ない」への対策として、改善案A〜E（fun-fix-proposal-v0.1）と並ぶ新要素案。

## Plague Inc.のバブル調査結果

### 種類と出現条件
- **オレンジ（DNAバブル）**: 感染した国からランダムに出現。序盤に多く、後半は減る。価値は1〜3ポイントのランダム
- **赤（バイオハザード）**: 新しい国に初めて感染した時に出現するイベント型。国ごとに1回だけ。価値は危険度に比例して増える
- **青（フラスコ）**: 治療研究機が着陸した国に出現。タップすると治療研究を遅らせる。**取り逃すと治療進行が約0.5%進む**（見逃しペナルティが焦りを生む）

### 頻度の設計（解析された出現確率式より）
- 基本の出現確率は約10%から始まり、**出現したバブルの総数が増えるほど下がる**（稼ぎすぎを防ぐ自己調整）
- 逆に「DNAが3ターン変わらない＝停滞している」と出現率が上がる補助（evoboost）が入っている。詰まったプレイヤーを助ける仕掛け
- 種類のローテーションでゲーム全体に役割分担がある: オレンジ=序盤、赤=序〜中盤、青=中〜終盤。常に「画面を見ている理由」がある

### 消滅と取り逃し
- どのバブルも数秒で消える。オレンジは取り逃しても後日また出る（優しい）。青は取り逃すとペナルティ（厳しい）。種類ごとに厳しさが違う
- スマホ版は一時停止中も消える仕様が「不親切」と批判されている。本作では真似しない

### 弾ける爽快感の正体
- 専任のサウンドデザイナーが「バブルの出現音とタップ音」の作り込みに特に苦労したと語っている。**音が爽快感の中心**
- 押した瞬間にポイント表示が増える即時フィードバックと、地図を常時スキャンする「探す→見つける→弾く」の短いループ
- 速く弾いても価値は変わらない（反射神経ではなく「見逃さない注意力」のゲームになっている）

## 本作への当てはめ（設計案）

### 不満バブル
- **出現条件**: 一定時間以上止まっている／待たされている人の頭上に出現（例: 待ちがゲーム内10分相当を超えた人から確率で）。不満の理由がある場所にだけ出るので、バブル自体が「ここが詰まっている」という情報になる
- **見た目**: 丸いバブルに不満マーク。中でゆらゆら揺れ、消える直前に縮み始めて寿命を予告する。画面の見やすさを守るため同時表示は最大3〜5個まで
- **寿命**: 実時間で約4〜6秒。速度設定に連動させない（早い速度で理不尽に短くしない）。**時間を止めている間はバブルも凍結**し、消えない
- **タップ判定**: カメラ移動のドラッグと区別する（動かさず離した時だけタップ）。設備タップより優先して判定

### 弾く感触
- タップで一瞬膨らんでから破裂し、破片が飛ぶ
- 「+5」がバブルから資金カウンターへ飛んでいく表示
- 破裂音は短く軽い音。短時間に連続で弾くと音程が少しずつ上がる（コンボ感）。音程のランダムな揺らぎで単調さを避ける
- 連続弾き（2.5秒以内の連鎖）はカウンタ表示だけに留め、ポイント計算は単純に保つ

### 頻度の目安
- ピーク時: 実時間5〜10秒に1個程度。閑散時はほぼ出ない（渋滞が無い所には出ない、という条件から自然にこうなる）
- 出現確率は「これまで出た総数」で少しずつ下げる（Plague Inc.式の自己調整）。逆に、資金が尽きて何もできない停滞時は少し上げる補助も同式で可能

### 稼ぎ目的の放置への対策
- バブルは「困っている人」から出るので、稼ごうとして渋滞を放置すると不満度が上がり敗北に近づく。リスクと報酬が釣り合う形にする
- 1人からは連続で出さない（クールダウン）。同時表示数の上限でも総量を抑える

## 決めなければいけないこと: ポイントの経済への組み込み方

現在の決定は「ステージ資金は固定（ステージ1は300）」。バブルのポイントをどう組み込むかで3案。

- **案1（推奨）: 2層にする**。開始資金は今までどおり固定で事前配置に使う。バブルで貯まるのは別枠の「開発ポイント」で、進行中の追加設置や間隔変更などにだけ使える。固定予算のパズル性を壊さず、途中にも「貯めて使う」判断が生まれる
- **案2: 資金に合算する**。開始資金を少なくし（例: 100〜200）、残りはバブルで稼ぐ。タップが必須の作業になりやすく、「眺める楽しさ」と衝突する恐れ
- **案3: ポイントではなく、その人の不満を少し下げる効果にする**。通貨にしない分、経済は今のまま。ただしユーザーの発案（ポイントで設置）からは外れる

## 既存の決定との関係
- 「眺めていて楽しい画面」との両立が条件。同時表示数の上限と控えめなデザインが必須
- 「予報は約束」には影響しない（バブルは予報された混雑から自然に発生する）
- 改善案E（資金の今使う／残すの選択）とは相互作用がある。案1なら両立しやすい
- 音は「最低限から始める」決定があるが、バブルの破裂音だけはこのシステムの気持ちよさの中心なので、最初から作り込む価値がある
