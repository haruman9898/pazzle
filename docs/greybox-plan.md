### Compatibility レンダラーによる制約（トラック2に影響）
Web 版で使える照明表現には上限がある。指向性ライトとその影、オムニ／スポットライト、フォグは使える。SSAO、SSR、SDFGI、ボリューメトリックフォグなどの高度な効果は使えない。ジオラマ感の照明は「ライト＋影＋色調（時刻で遷移）」を中心に設計する必要がある（ライトマップのベイクが Web でどこまで使えるかはトラック2で確認する）。

## 1. 作業計画

### 1.1 アーキテクチャ
- `sim/`（純ロジック、Node 非依存）: グリッド、車線・歩道グラフ、エージェント、信号、衝突回避、不満度、時間。固定ステップ（例: 30Hz）で進める
- `view/`（表示）: sim の状態を読んで箱を描く。マルチメッシュで車と歩行者を描き、数百体でも軽くする
- `ui/`: 上部バー、3本線ボタン、設置パネル、確定／キャンセル、FPS 表示
- `core/tuning.gd`: 試作で置いた初期値をすべてここに集約する（報告時にこのファイルを示す）

### 1.2 実装の順番
1. グリッドと1交差点（十字路、歩道、横断歩道候補）、四隅の発生・吸収エリア
2. カメラ（アイソメ、360度回転、ズーム、移動、定位置ボタン）とタッチ／マウス入力
3. 車両: 車線走行、直進・右左折、車間距離。信号なしの交差点挙動
4. 歩行者: 歩道を歩く、自分の進路上で無断横断、車を止めて渡る
5. 衝突回避（接触ゼロの保証）とヒヤリ判定・カウント
6. 信号機: 設置フロー（3本線 → 時間停止 → パネル → 仮配置 → 確定／キャンセル）、間隔プリセット3段階、資金300／費用100
7. 歩行者の横断歩道利用ルール（迂回距離パラメータ）
8. 不満度（個人・街全体）、上部バー、速度切替、失敗条件の内部カウント
9. 朝ピーク相当の時間帯プロファイルでのループ、調整
10. Web 書き出し、計測、報告レポート

### 1.3 計測
- 画面隅に FPS を常時表示する（仕様 1 章「試作段階からスマホブラウザで FPS を計測できる状態」）
- ヘッドレス Chromium の FPS はスマホ実機の値ではない。実機の FPS はユーザーに開いてもらって計測する（下記 Q5）

## 2. グリッド規約（提案・試作で置く初期値）

最終モデルと試作の規約を最初に揃えるための提案です。トラック2でも同じ規約を使います。

| 項目 | 提案値 |
|---|---|
| 1マスの大きさ | 1マス = 1ワールド単位 = 現実の約3m（車線1本の幅） |
| 道路 | 片側1車線 × 2（対面通行）＝ 2マス幅。両側に歩道各1マス |
| 高さ区分 | 0 = 地面（道路・歩道）、1 = 低層（〜1単位）、2 = 中層（〜2単位）、3 = 高層（3単位〜）。設備（信号機など）は区分 1 |
| ピボット | footprint の底面中心、地面高さ 0 |
| 向き | 回転は 90度単位で保持（モデルの向きのみ。カメラの自由回転とは別） |

## 3. 不明点・質問（回答待ち）

指示書に「曖昧な点は勝手に固定せず質問として挙げる」とあるため、以下を確認させてください。回答がなくても進められるものは、括弧内の仮案で進めます。

**Q1. 信号の秒数は「ゲーム内時間」か「実時間」か（最重要）**
通常速度では24時間 = 5分なので、ゲーム内の1分は実時間で約0.2秒です。信号サイクルを現実どおりゲーム内60秒にすると、実時間で0.2秒ごとに点滅して見えなくなります。同じ理由で、車や歩行者の移動速度もゲーム内時計とは別の尺度にする必要があります。
（仮案: エージェントの移動と信号は「通常速度での実時間の秒数」で定義し、速度切替で一緒に伸縮させる。時計はそれとは独立して24時間を5分で進む）

**Q2. 信号なしの交差点で「完全な詰まり」を許すか**
「信号が無ければ譲り合わず渋滞」と「事故は絶対に起きない（低優先側が必ず止まる）」を両立させると、全員が止まって永久に動かない状態が起こりえます。
（仮案: 永久停止は起こさない。交差点内の空き具合で順番に少しずつ抜ける。ただし無秩序なので効率は悪く、渋滞は伸びる）

**Q3. 信号プリセットの秒数の扱い**
context ファイルの「未決定（実装側で仮置きしないこと）」に信号の秒数が含まれていますが、指示書では「初期値を決めて報告すること」とあります。指示書を優先し、初期値を置いて報告します。食い違いの報告として挙げておきます。

**Q4. マウス操作の割り当て**
仕様はタッチ操作のみ定義しています。
（仮案: 左ドラッグ = 移動、右ドラッグ または 左長押し→ドラッグ = 回転、ホイール = ズーム）

**Q5. スマホでの動作確認の方法**
受け入れ基準5（スマホブラウザで動作・FPS 報告）には、スマホで開ける URL が必要です。Web 版は wasm が約40MB あり、Artifact（1ファイル16MBまで）では公開できません。現実的なのは GitHub Pages での公開です。公開は外部に出す操作なので、実施してよいか確認させてください（リポジトリが公開・非公開どちらかで条件が変わります）。

**Q6. トラック2（ジオラマ品質サンプル）の担当**
トラック2も Claude Code が作りますか。それとも別の担当ですか。

**Q7. 朝ピークのループの長さ**
通常速度ではゲーム内1時間 = 実時間12.5秒です。ゲーム内3時間のループは約37.5秒で、観察には短い可能性があります。
（仮案: ゲーム内 6:00〜10:00 の4時間（通常速度で約50秒）をループさせ、長さは調整可能にする）

**Q8. 軽微な指摘**
受け渡しプロンプトに「まず3ファイルを読んで」とありますが、渡すファイルは4つ（＋本件では context を含め5つ）です。全ファイルを読みました。
